## 这是什么

心潮念和 AI 之间要接三根线：

1. **桥**：心潮主动去找 TA。她在小屋里抱了 TA、留了话，或者 TA 自己在心潮里冒出一阵想念，心潮把这件事递到 Aru，叫醒 TA。**这根线你已经照适配器教程接好了。**
2. **此刻**：她在 Aru 里每发一句话之前，先给心潮报一次"她来了"（心跳），再取一小段"此刻"（TA 这会儿的想念、情绪），贴在她这句话后面一起交给模型。这样 TA 回话的时候知道自己此刻是什么状态。
3. **回传**：TA 回完以后，把"她说 + TA 回"这一轮交给心潮，心潮自己判断这算什么互动，那份想念才落得下来。

桥只管第 1 根。**第 2、3 根由这个网关来接**：Aru 没有办法自己在每句话前后去找心潮，但 Aru 能自己填"模型服务地址"。把这个地址填成网关，网关把请求原样转给真正的模型，路上顺手把第 2、3 根线接好。

```
手机上的 Aru ──→ 网关 ──→ 真正的模型（你原来在 Aru 里填的那家）
手机上的 Aru ←── 网关 ←── 真正的模型
                  ↕ 此刻、回传
                心潮念 ──→ 桥 ──→ Aru（第 1 根，照旧）
```

**桥和网关两个一起用才完整**：只有桥，TA 会被心潮叫醒，可平时聊天时不知道自己此刻的状态，心潮也不知道你们聊过；只有网关，心潮那边有动静时叫不醒 TA。

几件要先知道的事：

- **⚠️ 网关能看到全部聊天内容和你的模型钥匙。** 它就站在 Aru 和模型中间，每句话都从它手里过，模型的钥匙也存在它那台机器上。所以**只能自己搭、只给自己用**，别用别人搭好的网关，也别帮别人搭。
- **心潮出问题不影响聊天。** 心潮没开、太慢（每次最多等 3 秒）、报错，网关都照常转发，最多多等一会儿。
- **只动她最新那一句。** "此刻"只贴在最后一条消息后面，前面的聊天记录一个字都不改。
- **TA 的回复原样转。** 一个字一个字蹦出来的效果照旧。
- **日志里没有聊天内容。** 只有时间、做了哪一步、成功还是失败、用了多久、几个字。不记聊天内容，不记任何钥匙和口令。

（心潮念网关教程 · White-ting）

## 先看你能不能用

**网关只接 OpenAI 兼容格式**（Aru 里协议选「OpenAI 兼容」的那种）。DeepSeek、各种中转站、填 API Key 接的模型基本都是这种。

- **在 Aru 里用「订阅账号」登录 Claude 的，走不了网关。** Aru 只肯把订阅的登录凭证发给 Anthropic 官方地址，地址换成网关，Aru 在发出去之前就拦下了（测试时 Aru 直接报 `Claude subscription credentials can only be sent to api.anthropic.com`）。订阅那个供应商**保持原样、不用改**；它那边的回传照适配器教程第 8 步，让 TA 用心潮念的工具自己记。
- **混着用的**（比如 DeepSeek 填 Key、Claude 用订阅登录）：只把 DeepSeek 那个换成网关。用 DeepSeek 聊天时有此刻和回传，切到 Claude 订阅时照第 8 步。
- 网关的程序里其实还留着 Anthropic 格式和"透传"的代码，但没有真机测过，这份教程不教，也不建议用。

（心潮念网关教程 · White-ting）

## 先看你够不够条件

| 东西 | 说明 |
|---|---|

## 第 1 步：把网关放到跟桥同一台机器上

**为什么放这台**：心潮念就在旁边，网关找心潮走本机，又快又不用把心潮暴露出去；Node 也已经装好了，**网关和桥用同一个 Node**，不用另装。

1. 看一下 Node 的版本：

   ```
   node -v
   ```

   **成了的样子**：显示 `v20.6` 或更大的数字（`v22.…`、`v24.…` 都行）。比 `v20.6` 小的，去 Node.js 官网下一个 LTS 版装上。

2. 把压缩包里的网关文件夹放到 `/opt/xinchao-gateway`：

   ```
   sudo mkdir -p /opt/xinchao-gateway
   sudo chown $USER /opt/xinchao-gateway
   ```

   然后把压缩包里 `xinchao-gateway` 文件夹**里面的东西**传进 `/opt/xinchao-gateway/`（用终端的上传功能，或者 `scp`，跟上传适配器一样）。

3. 核对一下：

   ```
   ls /opt/xinchao-gateway
   ```

   **成了的样子**：能看到 `gateway.mjs`、`lib`、`.env.example`、`LICENSE`、`README.md` 这几样。

- **不用 `npm install`**：网关只用 Node 自带的东西，没有要装的包。
- 网关和桥是**两个独立的程序**，各开各的，互不影响。网关不会碰桥的文件夹，也不会读桥的 `.env`。

（心潮念网关教程 · White-ting）

## 第 2 步：填网关的 `.env`

网关的设置都在它自己文件夹里的 `.env`。先复制一份模板：

```
cd /opt/xinchao-gateway
cp .env.example .env
nano .env
```

要改的是下面五项，**每一项从哪拿**都写在右边：

| 名字 | 填什么 | 从哪拿 |
|---|---|---|
| `GATEWAY_KEY` | 网关自己的口令。**Aru 里"API Key"那一栏就填这一串** | 自己生成，见下面第 1 条 |
| `UPSTREAM_URL` | 真正的模型服务地址，写到 `/v1` 为止 | 你原来在 Aru 模型供应商里填的"服务地址"；或者模型服务商后台写的 API 地址 |
| `UPSTREAM_KEY` | 真正的模型的钥匙 | 你原来在 Aru 里填的那串 API Key；或者去模型服务商后台新建一把 |
| `XINCHAO_URL` | 心潮念的地址 | 跟心潮念在同一台就写 `http://127.0.0.1:18110`（跟适配器教程第 1 步 curl 用的是同一个） |
| `XINCHAO_TOKEN` | 心潮念的服务口令 | **心潮念 `.env` 里 `DYNAMIC_MIND_TOKEN=` 后面那一串** |

1. **生成 `GATEWAY_KEY`**：

   ```
   openssl rand -hex 24
   ```

   出来一串 48 个字的字母数字，复制下来填进 `GATEWAY_KEY=` 后面。等下在 Aru 里还要填一次，先存在只有你看得到的地方。**别跟桥口令、`DYNAMIC_MIND_TOKEN`、模型钥匙用同一串。**

2. **`XINCHAO_TOKEN` 最容易填错**：

   - 要填的是心潮念 `.env` 里的 **`DYNAMIC_MIND_TOKEN`**。
   - **不是**适配器教程第 1 步生成的**桥口令**（`BRIDGE_MACHINE_TOKEN`）。两串长得很像，但管的不是一回事：桥口令只能用来连桥，拿它去报心跳、取此刻，心潮念会拒收。
   - 测试的时候就有人填成了桥口令，结果日志里 `heartbeat`、`now`、`event` 三样全是 `status=401`。

   去心潮念那边找这一串（**别用 `cat` 看整个文件**，里面别的口令也会打在屏幕上）：

   ```
   grep -c '^DYNAMIC_MIND_TOKEN=' 心潮念目录/.env
   ```

   显示 `1` 就说明有这一行。然后用 `nano` 打开心潮念的 `.env`，把那一行等号后面的复制过来。

3. **`UPSTREAM_URL` 写到 `/v1` 为止**，后面不要再加 `/chat/completions`，也不要加 `/`。比如服务商写的是 `你的模型服务地址/v1/chat/completions`，这里就只写 `你的模型服务地址/v1`。
   - 你已经在用别的网关（比如记忆网关）的，这里就填那个网关的地址，两个叠着用：Aru → 心潮念网关 → 记忆网关 → 模型。

4. **在几家中转站之间换着用的**（比如今天聚梦、明天 noir），每家再加两行，名字只用大写字母和数字：

   ```
   UPSTREAM_JUMENG_URL=https://聚梦的地址/v1
   UPSTREAM_JUMENG_KEY=聚梦的钥匙
   ```

   第 5 步里 Aru 的服务地址写成 `https://你的地址/jumeng/v1` 就走这一家；不写名字（`https://你的地址/v1`）还走上面的 `UPSTREAM_URL`。以后换哪家，在 Aru 里改地址就行，不用再改网关。只用一家的跳过这一条。

5. 其他项先不用动，`.env.example` 里每一项都有中文说明。保存（Ctrl+O、回车，Ctrl+X 退出），然后只让自己能读：

   ```
   chmod 600 .env
   ```

6. 核对一下（两条命令都只打名字和数字，不打出值）：

   ```
   grep -cE '^(GATEWAY_KEY|UPSTREAM_URL|UPSTREAM_KEY|XINCHAO_URL|XINCHAO_TOKEN)=.+' .env
   grep -E '^[^#].*(换成|example)' .env | cut -d= -f1
   ```

   **成了的样子**：第一条打出 `5`（五项都填了）；第二条**什么都不打**。
   - 第一条不到 `5`：有哪项等号后面是空的。
   - 第二条打出了名字（比如 `UPSTREAM_KEY`）：这一项还是模板里的 `换成…` 或 `example`，没改成你自己的。

> 网关的 `.env` 里有**模型钥匙**和**心潮口令**两样，跟桥的 `.env`、`aru-bundle.json` 一样要藏好：别截图、别发人、别贴给 AI。

（心潮念网关教程 · White-ting）

## 第 3 步：先在本机开起来，用 curl 试

先手动开一次，确认网关自己、心潮、模型三头都通了，再去套 HTTPS。

1. **开网关**：

   ```
   cd /opt/xinchao-gateway
   node gateway.mjs
   ```

   **成了的样子**：

   ```
   心潮念网关 0.1.10 已启动：http://127.0.0.1:8790/v1（此刻 开，回传 开，心潮超时 3000ms）
   ```

   - 出来的是 `配置有问题（.env）：` 加几行中文：照它说的补上 `.env`，再开一次。
   - 这个窗口**别关**，日志就打在这里。下面的命令另开一个终端窗口跑。

2. **看网关活着没有**（这个地址不用口令）：

   ```
   curl -s http://127.0.0.1:8790/healthz
   ```

   **成了的样子**：

   ```
   {"ok":true,"version":"0.1.10","build":"dev","by":"White-ting"}
   ```

   `build` 后面可能不是 `dev`，是作者发给你那份的编号，这是正常的。

3. **用 curl 发一句聊天**。把 `你的口令` 换成 `GATEWAY_KEY` 那一串，`你的模型名` 换成你在 Aru 里用的模型名（网关不改模型名，原样转给模型）：

   ```
   curl -s http://127.0.0.1:8790/v1/chat/completions \
     -H "Authorization: Bearer 你的口令" \
     -H "Content-Type: application/json" \
     -d '{"model":"你的模型名","messages":[{"role":"user","content":"我在试网关"}]}'
   ```

   这一句**会真的报给心潮**（心跳和回传都会发），所以就写一句平常的话，别写奇怪的测试内容。

   **成了的样子**：
   - 这个窗口里出来模型的回复（一大段 `{"id":…,"choices":[…]}`，里面有 TA 回的话）。
   - 开着网关的那个窗口里多了这样几行（每行开头是时间，后面的数字每次都不一样）：

   ```
   … turn ok kind=her chars=5                    ← 认出是她在说话，这句 5 个字
   … heartbeat ok status=200 ms=8                ← 心跳报上了
   … now ok status=200 ms=5                      ← 取到了此刻
   … now-attach ok chars=42                      ← 此刻贴上了（42 个字）
   … request ok path=/v1/chat/completions status=200 ms=2310 stream=0
   … event ok status=200 ms=9                    ← 回传成功
   ```

   要看的是三样：**`kind=her`**、**`now-attach ok`**、**`event ok`**。三样都在，网关就通了。
   - `now-attach skip why=throttled` 或 `why=gate`：心潮那边是通的，只是这次没贴（见第 8 步）。也算通了。
   - `heartbeat`、`now`、`event` 后面是 `fail status=401`：`XINCHAO_TOKEN` 填错了，多半填成了桥口令。回第 2 步第 2 条。
   - 别的样子，翻到最后的"排错"。

4. 先**别关**这个手动开的网关，第 4、5 步还要用它。

（心潮念网关教程 · White-ting）

## 第 4 步：给网关一个公网 HTTPS 地址

手机上的 Aru 要从外面连到这台机器上的网关。**千万别把 `http://` 的网关直接开到公网**：口令和聊天内容会明文在网上走。做法跟适配器教程第 2 步给 Host 拿地址一样，用 cloudflared 的临时隧道，只是端口换成网关的 **8790**。

- 网关 `.env` 里的 `HOST` 保持 `127.0.0.1`，**不要改成 `0.0.0.0`**。隧道就在这台机器上，从本机连网关就够了。用 Caddy、Nginx 这类反代套 HTTPS 的也一样：反代在同一台机器上，就保持 `127.0.0.1`。改成 `0.0.0.0` 的话，只要服务器的防火墙或安全组放行了 8790，别人就能用 `http://你的IP:8790` 直连网关，口令和聊天内容都是明文。
- 给 Host 开的那条隧道（8787）**别动**，这里另开一条，两条各管各的。

1. **开一条隧道**，把网关的 8790 端口送到公网（日志文件换个名字，别跟 Host 那条混了）：

   ```
   nohup cloudflared tunnel --url http://127.0.0.1:8790 > /tmp/gw-tunnel.log 2>&1 &
   sleep 6
   grep -o 'https://[a-z0-9-]*\.trycloudflare\.com' /tmp/gw-tunnel.log | head -1
   ```

   **成了的样子**：出来一个 `https://一串单词.trycloudflare.com`，记下来，这就是**网关的地址**（下面写成 `https://你的地址`）。

2. **从外面试一下**：

   ```
   curl -s https://你的地址/healthz
   ```

   **成了的样子**：跟第 3 步一样，出来 `{"ok":true,"version":"0.1.10",…}`。也可以用手机浏览器打开 `https://你的地址/healthz`，看到同样的一行字就是通了。看到 Cloudflare 的报错页（写着 1033、502 之类），就是隧道没连上网关：看网关还开着没有。

> ⚠️ **这种临时隧道每次重开地址都会变**，机器重启以后它也不会自己起来。地址变了，要回 Aru 把服务地址改成新的（第 5 步）。哪天 Aru 突然连不上模型了，先查这个。
>
> **长期用要建固定隧道**，地址就一直不变。大概是这几步（要有一个自己的域名，交给 Cloudflare 管；具体照 Cloudflare 官方说明做，界面和命令以它为准）：
> 1. `cloudflared tunnel login`：在浏览器里登录 Cloudflare，选你的域名；
> 2. `cloudflared tunnel create xinchao-gw`：建一条有名字的隧道；
> 3. `cloudflared tunnel route dns xinchao-gw 你的地址`：把你域名下的一个子域名指到这条隧道；
> 4. `cloudflared tunnel run --url http://127.0.0.1:8790 xinchao-gw`：开隧道。想让它一直开着，照 Cloudflare 的说明把它装成系统服务。
>
> 用 Tailscale 也行，照它官方的说明做。不管哪种，都要是 `https://` 开头。

（心潮念网关教程 · White-ting）

## 第 5 步：在 Aru 里把模型地址换成网关

现在让 Aru 不再直接找模型，而是找网关。

> Aru 界面上的按钮具体叫什么，我们没有逐个核实过。下面照 Aru 手册里的说法写，**看不准的地方以你 App 里的为准**。

1. Aru → **总设置** → **模型供应商** → **API 与供应商**。
   - 可以**新建一个**供应商，原来那个先留着，网关出问题时能切回去。
2. 填这几项：
   - **供应商名称**：随便起，比如「心潮念网关」。
   - **服务地址**：`https://你的地址/v1`（第 4 步拿到的地址，后面加 `/v1`）。第 2 步加了几家中转站的，写 `https://你的地址/那一家的名字/v1`，比如 `…/jumeng/v1`；也可以每家建一个供应商。
   - **API Key**：`GATEWAY_KEY` 那一串（**不是**模型的钥匙。模型的钥匙从现在起只存在网关那台机器上，不再交给 Aru）。
3. 打开**高级设置**：
   - **协议**：选 **OpenAI 兼容**（网关只接这一种）。
   - **鉴权头**：用默认的就行（`Authorization: Bearer …`）。网关也认 `x-api-key`，所以改成那个也能用。
   - **路径**：用默认的（`/chat/completions` 这类），**别在服务地址里再写一遍**。
   - 这三项的叫法和默认值，以你 App 里的为准。
4. 点 **测试连接**。

**成了的样子**：
- Aru 里提示连接成功（具体怎么写以你 App 里的为准）。
- 开着网关的那个窗口里，能看到刚才测试的那个请求，比如 `request ok path=/v1/… status=200`。
  - 测试连接具体发的是什么请求，我们没核实过，所以这里可能还会多出 `turn ok kind=…` 之类的行，都正常。
  - 看到 `auth fail … status=401`：Aru 里的 API Key 跟 `GATEWAY_KEY` 对不上。
  - 网关窗口里**一行都没多**：请求根本没到网关，多半是服务地址填错了，或者隧道断了。用手机浏览器打开 `https://你的地址/healthz` 看看。
  - 看到 `path=/v1/v1/…`：Aru 自己会在地址后面加 `/v1`，把服务地址里的 `/v1` 去掉再试。
5. 把聊天用的模型换到这个新供应商下面（模型名照原来的填）。

- **Claude 用订阅账号登录的那个供应商别动**，保持原样直连。原因见开头「先看你能不能用」。

（心潮念网关教程 · White-ting）

## 第 6 步：让网关一直开着

关掉终端窗口，网关也就停了，Aru 就连不上模型了。所以要找一个程序看着它，停了就重开，机器重启也自己起来。

**先把第 3 步手动开的那个网关停掉**：在那个窗口按 Ctrl+C（窗口已经关了，或者是用 `nohup` 在后台开的，就跑 `pkill -f "node gateway.mjs"`）。不停掉的话，等下的那个会因为端口被占着开不起来（日志里写 `EADDRINUSE`）。

**Linux 服务器（systemd）**：

1. 先看 Node 装在哪：

   ```
   which node
   ```

   记下打出来的那一行，比如 `/usr/bin/node`。

2. 新建 `/etc/systemd/system/xinchao-gateway.service`（要 `sudo nano`），内容：

   ```
   [Unit]
   Description=心潮念网关
   After=network-online.target

   [Service]
   WorkingDirectory=/opt/xinchao-gateway
   ExecStart=/usr/bin/env node gateway.mjs
   Restart=on-failure
   RestartSec=10
   User=你的用户名

   [Install]
   WantedBy=multi-user.target
   ```

   - 网关自己会读它文件夹里的 `.env`，所以这里**不用**写 `--env-file`。
   - Node 是用 nvm 这类工具装的（`which node` 打出来的路径里有 `.nvm`）：把 `/usr/bin/env node` 换成 `which node` 打出来的完整路径。
   - `User=` 写你自己的用户名（`whoami` 能看到），要跟 `/opt/xinchao-gateway` 的主人是同一个，网关要往里面的 `state/` 写一个很小的节流记录。

3. 然后：

   ```
   sudo systemctl daemon-reload
   sudo systemctl enable --now xinchao-gateway
   systemctl status xinchao-gateway
   ```

   **成了的样子**：看到 `active (running)`。看它的日志：`journalctl -u xinchao-gateway -f`（Ctrl+C 退出看日志，网关不会停）。

**Mac（launchd）**：

1. 先看 Node 装在哪：`which node`，记下打出来的那一行，比如 `/usr/local/bin/node` 或 `/opt/homebrew/bin/node`。
2. 新建 `~/Library/LaunchAgents/local.xinchao-gateway.plist`，内容（三处 `你的用户名`、一处 Node 路径、网关文件夹的位置都换成你的。**路径都要写完整的**，从 `/` 开始，不能用 `~`）：

   ```xml
   <?xml version="1.0" encoding="UTF-8"?>
   <plist version="1.0">
   <dict>
     <key>Label</key>
     <string>local.xinchao-gateway</string>
     <key>ProgramArguments</key>
     <array>
       <string>/opt/homebrew/bin/node</string>
       <string>/Users/你的用户名/xinchao-gateway/gateway.mjs</string>
     </array>
     <key>WorkingDirectory</key>
     <string>/Users/你的用户名/xinchao-gateway</string>
     <key>RunAtLoad</key>
     <true/>
     <key>KeepAlive</key>
     <true/>
     <key>StandardOutPath</key>
     <string>/Users/你的用户名/Library/Logs/xinchao-gateway.log</string>
     <key>StandardErrorPath</key>
     <string>/Users/你的用户名/Library/Logs/xinchao-gateway.log</string>
   </dict>
   </plist>
   ```

3. 然后：

   ```
   launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.xinchao-gateway.plist
   launchctl list | grep xinchao
   ```

   **成了的样子**：`launchctl list` 那一行最前面是一个数字（网关的进程号），不是 `-`。看日志：`tail -f ~/Library/Logs/xinchao-gateway.log`。
   - 要停掉：`launchctl bootout gui/$(id -u)/local.xinchao-gateway`。改了 plist 要先停再 `bootstrap` 一次。
   - Mac 睡着了网关也会停，Aru 就连不上模型。Mac 当服务器用的，记得在系统设置里关掉自动睡眠。

> **隧道也要一直开着**：网关一直开着，隧道断了手机照样连不上。第 4 步的临时隧道机器重启后不会自己起来，地址还会变；长期用请照第 4 步后面的说明建固定隧道，并把它装成系统服务。

（心潮念网关教程 · White-ting）

## 第 7 步：确认真的通了

1. **在 Aru 里跟 TA 聊一句**，平常说话就行。
2. **看网关的日志**（Linux：`journalctl -u xinchao-gateway -f`；Mac：`tail -f ~/Library/Logs/xinchao-gateway.log`）。

   **成了的样子**（跟第 3 步差不多，最后一行 `stream=` 后面多半是 `1`，因为 Aru 聊天是一个字一个字蹦出来的）：

   ```
   … turn ok kind=her chars=6
   … heartbeat ok status=200 ms=8
   … now ok status=200 ms=5
   … now-attach ok chars=42
   … request ok path=/v1/chat/completions status=200 ms=2310 stream=1
   … event ok status=200 ms=9
   ```

   - "此刻"每句都贴，第二句起也应该是 `now-attach ok`。
   - 第二句起看到 `event skip why=throttled` 是**正常的**：回传不会每句都发（见第 8 步）。
3. **再看心潮小屋**：那边会显示"她来了"。这就是网关替你报的心跳（小屋里具体怎么写，以你心潮念的版本为准）。

**三样都对上**（Aru 里 TA 正常回话、日志里有 `kind=her` 和 `ok`、小屋里看到她来了），网关就接通了。

4. **顺便看一眼桥递消息时的样子**：在心潮小屋里点一下互动，桥会把它递到 Aru、叫醒 TA。TA 被叫醒以后去问模型的那一下，日志里应该是 `turn ok kind=skip`：开头是 `【` 或 `〔心潮念` 的消息是桥递进来的，**不算她在说话**，网关不报心跳、不回传。这是对的。
   - 这一下要是写着 `kind=her`：说明 Aru 在桥的消息前面加了别的字。在 `.env` 的 `SKIP_PREFIXES` 里用 `|` 把那几个字加上（比如 `SKIP_PREFIXES=【|〔心潮念|那几个字`），重启网关。

（心潮念网关教程 · White-ting）

## 第 8 步：几种"没有发生"，和后台杂活

**"此刻"每句都贴（0.1.3 起），回传不是每句都发。** 回传太密会刷屏，所以有节流：

日志每行第三个词：`ok` 做成了，`skip` 照规矩跳过（正常），`wait` 在等工具走完（正常），`fail` 才是真出错（0.1.10 起这样分，以前跳过也写成 `fail`）。


| 日志里写的 | 意思 | 要不要管 |
|---|---|---|
| `now-attach skip why=throttled` | 只在 `.env` 里把 `NOW_REPEAT_MIN` 改大了才有：心潮的"此刻"跟上次一样，这么多分钟内不重复贴。默认（0）每句都贴 | 不用，正常 |
| `now-attach skip why=gate` | 心潮给的内容没通过网关的检查（太长、行太多、带了小数或英文键名），这次没贴 | 不用，正常 |
| `event skip why=throttled` | 回传太密，这次跳过。两次至少隔 8 分钟、每小时最多 4 次；她隔了 45 分钟以上才说的第一句一定发 | 不用，正常 |
| `turn ok kind=skip` | 这句开头是 `【` 或 `〔心潮念`（桥递进来的），跳过。Aru 在前面并了发送时间之类的附注也认得出（0.1.4 起先去掉附注再看） | 不用，正常 |
| `turn ok kind=skip why=annotation` | 这一轮只有 Aru 加的附注（发送时间、环境信息），去掉以后没有她的话，不算她在说话 | 不用，正常 |
| `event wait why=tool-calls` | TA 这一轮去调工具了，先记下她那句，等工具走完再回传 | 不用，正常 |
| `turn ok kind=tool` | 工具调用的中间回合，跳过。工具全部走完、TA 说完最后一段，才配成一轮回传。后面带 `after=annotation` 的是 Aru 在工具结果后面又塞了一条附注，同样算工具回合 | 不用，正常 |
| `event skip why=tool-no-pending` 或 `why=tool-expired` | 工具走完了，但没找到她说的那一句（不是她起的头），或者离她那句超过 15 分钟 | 偶尔有不用管 |
| `turn ok kind=background` | 网关觉得这是 Aru 在后台干杂活，不是她在说话，跳过 | 看下面 |
| `event fail why=empty-reply` | TA 这一轮的正文是空的，没什么可回传。多半是 Aru 里"最大回复长度"设得太小，被模型的思考吃光了 | 把回复长度调大 |

这些数字都在 `.env` 里能改（`NOW_REPEAT_MIN`、`EVENT_MIN_INTERVAL_MIN` 这些），一般不用动。

**后台杂活（`kind=background`）**

有的 App 会拿同一个模型地址，偷偷做一些"不是聊天"的事：给对话起标题、写摘要、整理记忆、打标签。这些请求要是被当成她在说话，心潮就会以为她来了、聊过了，其实她根本没说话。网关会挡两种，日志里写 `turn ok kind=background`，后面的 `why=` 说是哪一种：

- **`why=max_tokens`**：请求里把回复长度限得很小（`max_tokens` 不超过 `BG_MAX_TOKENS`，默认 120）。起标题、写摘要一般只要几十个字，正常聊天不会这么限。
- **`why=pattern`**：请求里一条 TA 的回复都没有（单发的），而且系统提示或这句话里有"标题、摘要、总结、title、summary"这类词（`BG_PATTERNS`）。正常聊天都带着前面的对话，所以你在聊天里说"帮我总结一下"照样算你在说话。

**什么时候要改：**

- **她明明在聊天，日志却写 `kind=background why=max_tokens`**：你在 Aru 里把"最大回复长度"设得很小（120 以下）。把 `BG_MAX_TOKENS` 改得比你设的那个数小，或者写 `BG_MAX_TOKENS=0` 不看这一条。
- **她明明在聊天，日志却写 `kind=background why=pattern`**：多半是你的系统提示（人设）里正好有"标题""总结"这类词，而这是新对话的第一句。把 `BG_PATTERNS` 里那个词删掉；不想要这一条就写成 `BG_PATTERNS=`（等号后面空着）。
- **Aru 在后台干活，日志却写着 `kind=her`**（比如你没说话，日志里却冒出一行 `kind=her`，小屋里也显示她来了）：网关没认出来。可以把那类请求里会出现的词加进 `BG_PATTERNS`，用 `|` 隔开；还不行就看下面的 `ONLY_STREAM`。

**`ONLY_STREAM`（一般不用开）**

后台杂活一般是一次性回完的（非流式），聊天是一个字一个字蹦出来的（流式）。`.env` 里写 `ONLY_STREAM=true`，网关就只把流式的请求当成她在说话。

**⚠️ 打开之前一定先确认你的聊天是流式的**：

- 在 Aru 里聊一句，看 TA 的回复是不是一个字一个字蹦出来的；
- 再看日志里那一句的 `request ok … stream=1`。是 `stream=0` 就**别开**。

聊天要是非流式的，打开以后网关再也认不出她在说话，此刻和回传两根线就都不工作了，日志里会一直是 `kind=skip`，没有 `kind=her`。

改完 `.env` 都要重启网关才生效：Linux `sudo systemctl restart xinchao-gateway`；Mac 先 `bootout` 再 `bootstrap`（见第 6 步）。

（心潮念网关教程 · White-ting）

## 要先知道的

- **网关停了，Aru 就连不上模型。** 这跟桥不一样：桥停了只是心潮叫不醒 TA，聊天照旧；网关停了，聊天本身就断了。网关出问题又一时修不好，在 Aru 里先把模型切回原来那个供应商（第 5 步留着的那个），聊天就恢复了，只是暂时没有此刻和回传。
- **心潮停了不影响聊天。** 每句话最多多等 3 秒（`XINCHAO_TIMEOUT_MS`）。心潮要长时间关着，可以把 `NOW_ENABLED` 和 `EVENT_ENABLED` 都改成 `false`，连这 3 秒都省了。
- **模型报的错原样给 Aru。** 额度用完（429）、参数不对（400）这些，网关不改，Aru 里看到的就是模型那边的错。
- **重启网关，节流不会乱。** 节流记录存在网关文件夹的 `state/` 里，重启以后还在。
- **用的是临时隧道的话**：地址一变，Aru 里的服务地址就要跟着改。

## 排错

| 看到的 | 多半是 | 怎么办 |
|---|---|---|
| 开网关时 `需要 Node.js 20.6 以上` | Node 太老 | 去 Node.js 官网装 LTS 版。systemd 里用的 Node 跟终端里的不是同一个的，照第 6 步写完整路径 |
| 开网关时 `配置有问题（.env）：` | `.env` 有必填项没填 | 照它列出来的补上；`.env` 要在网关文件夹里，名字正好是 `.env` |
| 开网关时 `EADDRINUSE` | 8790 已经有一个网关在跑了（多半是手动开的那个没停） | `pkill -f "node gateway.mjs"`，再开 |
| 日志 `auth fail … status=401`，Aru 报 401 | **网关口令填错了**：Aru 里的 API Key 跟 `GATEWAY_KEY` 对不上 | Aru 里填 `GATEWAY_KEY` 那一串，不是模型的钥匙。改过 `.env` 要重启网关 |
| 日志 `heartbeat fail status=401`、`now fail status=401`、`event fail status=401` | **心潮口令填错了**：`XINCHAO_TOKEN` 不是 `DYNAMIC_MIND_TOKEN`，多半填成了桥口令 | 照第 2 步第 2 条改成心潮念 `.env` 里的 `DYNAMIC_MIND_TOKEN`，重启网关 |
| 日志 `heartbeat fail why=error`（`now`、`event` 也一样） | 心潮连不上：没开，或者 `XINCHAO_URL` 写错了 | 心潮念那边开着没有；`XINCHAO_URL` 不带 `/v1`，跟心潮念在同一台就是 `http://127.0.0.1:18110`。聊天不受影响 |
| 日志 `heartbeat fail why=timeout` | 心潮太慢，3 秒没回 | 看心潮念那台机器忙不忙。聊天不受影响 |
| 日志 `upstream fail … why=ECONNREFUSED`（或 `ENOTFOUND`），Aru 报 502 | 网关连不上模型：`UPSTREAM_URL` 写错了 | 写到 `/v1` 为止，前面是 `https://`；拿模型服务商写的地址核对一遍 |
| 日志 `request fail … status=401`（不是 `auth fail`） | 模型那边不认钥匙：`UPSTREAM_KEY` 错了或者过期了 | 换成正确的模型钥匙，重启网关 |
| 日志 `request fail … status=429`、`400`、`404` 这类 | 模型那边报的错（额度、参数、模型名），网关原样转 | 照模型服务商的说明查；模型名照原来在 Aru 里的填 |
| 日志 `request fail path=/v1/v1/…` | 地址里多了一个 `/v1` | Aru 的服务地址或 `UPSTREAM_URL`，有一边多写了 `/v1`，去掉 |
| Aru 测试连接失败，网关日志一行都没多 | 请求没到网关：服务地址写错，或者隧道断了、地址变了 | 手机浏览器打开 `https://你的地址/healthz`；打不开就照第 4 步重开隧道，把新地址填回 Aru |
| Aru 测试连接失败，网关日志里有 `auth fail` | 网关口令不对 | 见上面第 4 行 |
| Aru 测试连接失败，网关日志里有 `upstream fail` 或 `request fail` | 网关到了，模型那边没通 | 见上面 `upstream fail`、`request fail` 那几行 |
| Aru 报 413 | 发的东西太大（多半是图片） | `.env` 里把 `MAX_BODY_MB` 调大一点，重启网关 |
| 日志里一直没有 `kind=her`，全是 `kind=skip` | ① 打开了 `ONLY_STREAM`，而聊天是非流式的；② 她的消息开头正好是 `【`，或者 `SKIP_PREFIXES` 里加了太短的字 | ① 看 `request ok … stream=` 是不是 `0`，是的话把 `ONLY_STREAM` 改回 `false`；② 看 `SKIP_PREFIXES` 那一行，她自己说话尽量别用 `【` 开头 |
| 日志里一直没有 `kind=her`，全是 `kind=background` | 后台杂活的判断把聊天也挡了 | 照第 8 步改 `BG_MAX_TOKENS` 或 `BG_PATTERNS` |
| 日志里一直没有 `kind=her`，连 `turn` 那行都没有，只有 `request` | 网关没认出最后一条是她说的话（比如 Aru 这一下发的不是聊天请求） | 在 Aru 里正常聊一句再看；一直这样就截日志（日志里没有正文）问人 |
| "此刻"每句都没贴，日志里是 `now-attach skip why=throttled` | `.env` 里 `NOW_REPEAT_MIN` 不是 0。从 0.1.2 或更早升级上来、照旧模板抄过 `NOW_REPEAT_MIN=30` 的，就会这样 | 改成 `NOW_REPEAT_MIN=0`，重启网关。默认每句都贴 |
| "此刻"每句都没贴，日志里是 `now-attach skip why=gate` | 心潮给的内容没通过检查。也是正常的 | 不用管。一直这样的话，看心潮念那边"此刻"给的是什么 |
| 日志里连 `now-attach` 那行都没有 | 心跳或取此刻失败了（往上看 `heartbeat`、`now` 那两行），或者 `NOW_ENABLED=false` | 照上面心潮 401、连不上那几行查 |
| 小屋里不显示"她来了" | 日志里 `heartbeat` 不是 `ok` | 照上面心潮那几行查 |
| 加了几家中转站，地址写 `…/那一家/v1` 却是 401、日志 `auth fail path=/***/v1/…` | 网关不认这个名字，当成了地址口令：名字拼错了，或者 `.env` 里那两行没写全、改完没重启 | 启动那一行要有 `渠道：…`，名字跟地址里的对上（不分大小写） |
| 机器重启以后 Aru 连不上 | 临时隧道没自己起来，或者地址变了 | 重做第 4 步，把新地址填回 Aru；长期用建固定隧道 |

## 隐私和安全

- 网关这边一共两样钥匙：**`GATEWAY_KEY`**（Aru 和网关之间）、**`UPSTREAM_KEY`**（网关和模型之间）；再加上它要用的心潮念 **`DYNAMIC_MIND_TOKEN`**。都在网关的 `.env` 里，这个文件要 `chmod 600`，别截图、别发人、别贴给 AI。
- 哪样漏了就换哪样：`GATEWAY_KEY` 重新 `openssl rand -hex 24`，网关和 Aru 两边一起改；模型钥匙去模型服务商后台作废、新建一把；`DYNAMIC_MIND_TOKEN` 照心潮念的说明换，换完网关的 `XINCHAO_TOKEN` 也要跟着改。
- **网关看得到全部聊天内容和模型钥匙**，所以只搭在你自己的机器上，只给你自己用。别用别人的网关，也别帮别人代搭。
- 网关的日志里只有时间、步骤、成败、耗时、字数，没有聊天内容和钥匙，截日志问人是安全的（截之前还是看一眼）。

## 给带你装的 AI

如果你是 AI，正在照这份教程带一个人接心潮念网关，请照下面做：

- **一次只带一步**，等对方说做好了、并且看到了"成了的样子"，再往下。
- **口令和钥匙绝不进对话**：不向对方要 `GATEWAY_KEY`、模型钥匙、`DYNAMIC_MIND_TOKEN`、桥口令，也不让对方把 `.env` 的内容贴进来，哪怕是为了帮忙核对。要核对，就让对方自己对比前四个、后四个字。万一已经发出来了，告诉对方去换（见"隐私和安全"）。
- **没有原版网关时别补**：这份教程本身不含网关代码。对方手上没有原版网关文件夹，就请对方去 github.com/White-ting/Aru-kit 的 Releases 下载原版压缩包，**不要照着教程自己写一个**，也不要用网上别人转来、改过的版本（许可不许转发）。
- **Aru、心潮念的界面和版本对不上时别编**：请对方截图（遮住口令）或描述屏幕上的字，照实际看到的带。
- **卡住了**：先对照"排错"那张表，再看网关日志里写了什么（只会写步骤、成败、耗时、字数，不会有正文）。
