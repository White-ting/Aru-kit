# 更新说明

最新的在最上面。日期是北京时间。

## v2.3.1（2026-11-23）

### 修正
- **开了小模型的，「刷太久差一点」同一段只问一次**：刷到规则的六成（默认 120 分钟就是 72 分钟）时会问一次小模型。v2.3 把几个 App 接成一段以后，六成到满之间每关一次 App 都会问一次，来回切得勤的话一段能问十几次，白花 Workers AI 的额度。现在同一段只问一次，放下手机、重新开始一段才再问。
- 没开小模型的（默认没开）不受影响，可以不换。

## v2.3（2026-11-23）

### 新功能
- **几个 App 来回切也算刷太久**：以前「刷太久」只看一个 App 从打开到关掉，在抖音、小红书、QQ 之间切来切去，每段都不够长，就一直不敲。现在关掉一个 App、5 分钟内又打开下一个（`long_session.gap_min`），就算同一段，从这一串最早那次打开算起。叫醒理由会写「在微信、小红书、抖音之间连着刷了 45 分钟」。`gap_min` 填 0 就跟以前一样只算单个 App。
- **一段只敲一次**（`long_session.once`，默认开）：这一段刷满了敲过一次，接着刷就不再敲；放下手机超过 `gap_min` 分钟、重新开始一段，刷满了才再敲。填 `false` 就是冷却时间过了接着敲。
- 守门人只看得到你做了「打开 / 关掉」快捷指令的那几个 App；中间去了别的 App，它会以为你放下了手机。

### 两项新设置（在管理页「叫醒说明」的 `long_session` 里，不写就用默认）
| 设置 | 默认 | 意思 |
|---|---|---|
| `gap_min` | `5` | 关掉一个 App 后，空多少分钟以内又打开下一个，算同一段连着刷。填 `0` 就跟以前一样只算单个 App |
| `once` | `true` | 同一段只敲一次。填 `false` 就是冷却时间一过接着敲 |

**改 `long_session` 要整块写全**：保存叫醒说明时，`long_session` 这一组是整块换掉的。只写 `"long_session": { "gap_min": 0 }`，`minutes` 会变回默认的 120、`apps` 变回全部 App。要这样写：

```json
"long_session": { "enabled": true, "minutes": 120, "apps": [], "gap_min": 5, "once": true }
```

### 升级
- 照教程 4.3 换上新的 `worker.js`，点 Deploy。数据库、设置、记录都不用动；叫醒说明里没写 `gap_min`、`once` 的，自动用 5 分钟和「一段只敲一次」。管理页最底下显示 v2.3 就换好了。
- 想跟以前一模一样只算单个 App：在 `long_session` 里加 `"gap_min": 0`（记得整块写全，见上面）。

## v2.2（2026-11-19）

### 新功能
- **填错设置会提醒**：保存前会检查每天上限、冷却时间、时段、时区、地点列表这些。哪一项填错、该怎么填，管理页会用中文说清楚。原来的写法照旧能用：`dedupe_min` 填 0 还是不防刷屏，「到几点」填 24 还是到半夜。

### 修正
- **叫醒简报也只留 14 天**：跟时间线和检查记录一起自动清理。
- **投递失败不扣次数**，也不开始平常的叫醒冷却。要是 Host 没开，守门人会先等 10 分钟再试；管理页能看到是失败了，还是正在等。管理页的「测试敲门」不受这 10 分钟限制，失败了也不算，方便刚搭好时改完马上再试。
- **几条报告一起到，不会同时敲门**。补报仍可按发生时间放进时间线，但不能把她现在的状态拨回去；冷却、每天上限和防重复按收到的时间算。填了比收到时间还晚 5 分钟以上的时间，就按收到的时间记。

### 安全
- **管理口令不用再放在问号后面**：可以在管理页粘贴，或用 `#key=` 链接。打开后会从地址栏去掉，留在当前标签页，关掉就忘。旧 `?key=` 链接只用来帮你换过去；如果口令曾放在问号后面，建议换一把。快捷指令和管理请求都要把口令放在请求头里。
- Aru 外部触发的投递地址和外部小模型地址只收 HTTPS，不用明文 HTTP。

## 2026-10-23

### 新功能
- **四种新事件**：`battery_low` / `battery_ok`（电量低、电量回来了，`level` 0–100，写 `18%` 也认）、`focus_change`（专注模式开关，`mode` 是 work / dnd / sleep 或中文 工作 / 勿扰 / 睡眠，`active` true / false）、`mood`（手动点的心情：happy / low / alone / need_company，或 开心 / 低落 / 想独处 / 想聊天）。字段不对会回清楚的错误。
- **状态保护**：开着工作或勿扰专注模式时，"App 待太久""小模型""很久没动静""下班"这几种平常的关心先不叫；点了"想独处"后 `mood.alone_hours`（默认 4）小时内，除了关注的地点都不叫。睡眠专注模式等于就寝/起床。插上充电或报了 `battery_ok` 就解除电量低。
- **想聊天**：点了就直接叫醒 AI，睡觉、专注、独处都不拦；冷却单算 `mood.cooldown_min`（默认 15 分钟），每天上限照样算。
- **下班确认**：工作模式关掉、`work_end.confirm_min`（默认 15）分钟内没再打开才算下班，短暂关一下再开不算，开始时间照旧。默认只记不叫（`work_end.wake`）。
- **很久没动静**：`inactivity.from`～`to` 点之间，`hours`（默认 3）小时没有可信的活动（打开/关掉 App、到达/离开、起床、点心情；充电、电量、专注模式、备注不算），先记"先等等"，下一次定时还没动静才算一次；同一段只算一次，电量低时不当真。跟小模型开没开无关。默认只记不叫（`inactivity.wake`）。
- **她现在**：简报、小模型的提示、管理页新加一栏，写她现在的状态，比如"在工作（09:02 开始），手机电量低（20%）"。时间线里专注模式、心情写成人话。
- 定时任务用 Cloudflare 给的 `scheduledTime`；管理页「小模型」一栏改名「小模型和定时检查」，下班、没动静的检查结果也记在里面。
- 教程新加第 9 步（电量、专注模式、心情快捷指令怎么建）、第 5 步补了三项设置的说明、排错表补了几行。
- "很久没动静"每天从检查时段开始（`inactivity.from` 点）算起，早上不会把一整夜（在睡觉）算成没动静；出了时段，没确认完的"先等等"作废，第二天重新等。
- 点"想聊天"叫醒时，简报开头直接写"她刚在手机上点了「想聊天」，是她自己想让你来找她"。
- 叫醒说明里一组设置被写成 `null` 或数字时，用默认的，守门人不再整个报错。
- 测试从 33 项加到 76 项，`src/` 和合成的 `dist/worker.js` 都跑过。

## 2026-10-20

### 新功能
- **小模型**（可选）：规则管不到的时候（"差一点"、"今天跟平时不一样"），替 AI 看一眼要不要叫醒它。白天每 30 分钟看一次，事件差一点碰到规则时也看；只回"叫/不叫 + 一句理由"，不跟你说话，说叫也要过硬底线，自己每天另有上限。默认用 Cloudflare 的 Workers AI（数据不出 Cloudflare），也能换成 OpenAI 兼容的接口。管理页新加「小模型」一栏，能看它每次的判断，还能"现在问它一次"（只问不敲门）。教程第 7 步。在真的 Workers AI 上实测过。
- 简报里加了一行「她今天：」的摘要（几点起床、各 App 开了几次待了多久、去过哪）。

### 修正

- 定时任务建议改成每 30 分钟（`*/30 * * * *`），以前的 `17 * * * *` 照样能用，只是小模型一小时才看一次。
