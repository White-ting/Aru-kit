## 这是什么

心潮念有一座官方的「动态桥」：她在心潮小屋里抱了 TA、留了一句话、约了个时间，或者 TA 自己在心潮里冒出一阵想念，心潮都会把这件事递出去。官方给的接法是递进电脑上的终端窗口，或者你自己写的网页。

这份教程多接一条路：**递到 Aru 里**。用的是 Aru 自带的「外部触发」：心潮那边一有动静，Aru 里的 TA 就被叫醒，读到这件事，**自己决定要不要来找你、说什么**，不想说也可以不说。

```
心潮小屋 / 心潮自己的变化
      ↓  （心潮念服务端排好队）
心潮念官方动态桥（Runtime Bridge）
      ↓  每来一条，叫一次本教程的适配器
aru-adapter.mjs：加密，投给你的 Aru Host
      ↓  （Host 只当门铃，读不到内容）
手机上 Aru 里的 TA 被叫醒，自己决定说不说
```

TA 收到的样子大概是：

```
〔心潮念 · 动态桥〕这是她在心潮小屋里做的事，经心潮递过来的，不是她在 Aru 里发的消息。
【小屋桥·互动】她抱了你一下（小屋桥递的，心里有数就行，不用特意回。）
```

心潮自己冒出来的那种，开头会写"这是你自己在心潮里浮上来的感觉，不是她发的消息"，后面跟着【心潮】……

## 三根线，先看你是哪种

心潮念和 Aru 里的 TA 之间，一共要接三根线：

1. **桥**（心潮 → TA）：心潮那边有动静，递到 Aru、叫醒 TA。第 1～7 步。
2. **此刻**：她每说一句，TA 先知道自己这会儿是什么状态（想念、情绪、刚发生过什么）。
3. **回传**：聊完以后让心潮知道你们聊过，那份想念才落得下来。

第 2、3 根有两种接法，看你在 Aru 里是怎么接模型的：

| 你在 Aru 里怎么接模型 | 第 2、3 根怎么接 | 做哪几步 |
|---|---|---|
| 填 API Key（DeepSeek、中转站这类，OpenAI 兼容） | **网关**：每句自动贴此刻、自动回传，不用 TA 自己记 | 第 1～7 步，再做第 9 步 |
| Claude 用「订阅账号」登录 | **MCP**：TA 自己调心潮念的工具，一段聊天记一次 | 第 1～8 步 |
| 两种都有 | 填 Key 的走网关，订阅的走 MCP | 第 1～9 步都做 |

只想先接第 1 根的，做完第 7 步就能用，第 8、9 步以后再补也行。

| 东西 | 说明 |

## 第 1 步：心潮念那边打开桥

1. 先生成一串桥专用的口令。在心潮念那台机器的终端里跑：

   ```
   openssl rand -hex 32
   ```

   会出来一串 64 个字的字母数字，这就是**桥口令**。先复制到一个只有你看得到的地方，下面要用两次。**别发给任何人，也别贴给 AI。**

2. 打开心潮念的 `.env`（心潮念目录里的那个），找到或加上这三行：

   ```
   BRIDGE_ENABLED=true
   BRIDGE_MACHINE_TOKEN=刚才那串桥口令
   BRIDGE_SELF_SIGNALS=true
   ```

   - `BRIDGE_SELF_SIGNALS=true`：TA 自己在心潮里的变化（驱力冲顶、想念、醒来的余韵这些）也递过来。只想要"她在小屋里做的事"，就写 `false`。
   - 桥口令要跟 `DYNAMIC_MIND_TOKEN` **不一样**。

3. 让心潮念读到新设置。照心潮念说明里的写法重启，一般是在心潮念目录里：

   ```
   docker compose up -d --build --no-deps dynamic-mind
   ```

4. 检查一下（把 `桥口令` 换成你那串）：

   ```
   curl -s -H "Authorization: Bearer 桥口令" http://127.0.0.1:18110/bridge/v1/health
   ```

   **成了的样子**：屏幕上出现 `{"protocol":"xinchao-bridge-server/1","status":"ok"}`。

（心潮念 → Aru 适配器 v1.2 · White-ting）

## 第 2 步：给 Aru Host 一个公网 HTTPS 地址

> 这一步来自 **罐儿** 的补充。Host 已经有 `https://` 地址、手机在外面也连得上的，跳过这一步。
> 下面按"Host 装在 Linux 服务器上、用 systemd 跑（服务名 `aru-selfhost`）、端口 8787"写。你的端口不一样就换成你的。

**先做这一步，再去 Aru 里建触发器**：第 3 步导出的发送凭证里写着 Host 的地址，地址要先定下来。

1. **装 cloudflared**（Cloudflare 的隧道程序。系统自带的软件源里一般没有，直接下官方的程序）。先看机器是哪种 CPU：

   ```
   uname -m
   ```

   显示 `x86_64` 就用下面这条；显示 `aarch64` 就把命令里的 `amd64` 换成 `arm64`：

   ```
   sudo wget -q https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -O /usr/local/bin/cloudflared
   sudo chmod +x /usr/local/bin/cloudflared
   cloudflared --version
   ```

   **成了的样子**：出来一行 `cloudflared version 2026.…`。
   - 服务器连不上 GitHub（国内服务器常见）：在自己电脑上从同一个地址下载好，再用终端的上传功能传到服务器的 `/usr/local/bin/cloudflared`。网上有一些"GitHub 加速"的代理网址也能下，那是别人的服务器，用不用你自己定。

2. **开一条临时隧道**，把 Host 的 8787 端口送到公网：

   ```
   nohup cloudflared tunnel --url http://127.0.0.1:8787 > /tmp/tunnel.log 2>&1 &
   sleep 6
   grep -o 'https://[a-z0-9-]*\.trycloudflare\.com' /tmp/tunnel.log | head -1
   ```

   **成了的样子**：出来一个 `https://一串单词.trycloudflare.com`，记下来，这就是 Host 的新地址。用手机浏览器打开它，**只要不是 Cloudflare 的报错页**（写着 1033、502 之类）就是通了。

   > ⚠️ 这种临时隧道**每次重开地址都会变**，服务器重启以后它也不会自己起来。地址变了，要把下面第 3 小步重做一遍，**还要回第 3 步重新导出发送凭证、换进 `aru-bundle.json`**（凭证里写的是旧地址）。想要地址一直不变，得用 Cloudflare 的固定隧道（要有自己的域名）或者 Tailscale，照它们官方的说明做。

3. **把新地址告诉 Host**。先看 Host 的设置文件在哪：

   ```
   systemctl cat aru-selfhost.service
   ```

   里面有一行 `Environment=ARU_SELFHOST_CONFIG_FILE=/etc/aru-selfhost/node.env`，真正的设置在这个文件里。先备份一份，再打开它：

   ```
   sudo cp /etc/aru-selfhost/node.env /etc/aru-selfhost/node.env.bak
   sudo nano /etc/aru-selfhost/node.env
   ```

   找到 `ARU_BASE_URL=` 那一行，把等号后面整个换成上一步的 `https://…trycloudflare.com`（后面不要加 `/`），Ctrl+O、回车保存，Ctrl+X 退出。然后：

   ```
   grep '^ARU_BASE_URL=' /etc/aru-selfhost/node.env
   sudo systemctl restart aru-selfhost
   ```

   **成了的样子**：`grep` 打出来的那行是你的 `https://` 新地址；回到手机上 Aru → 自托管节点，刷新一下，能看到这条 https 地址连上了（延迟一两秒是正常的）。
   - 同一个文件里的 `ARU_TRANSPORT_KIND=lan` **不用动**。Aru 会把它标成「局域网」，看着有点怪，但能连。

## 第 3 步：在 Aru 里建一个「外部触发器」

1. Aru → 打开你的**协作者** → **主动** → 上面切到 **外部触发**。
2. 新外部触发器：
   - **名称**：起个正式点的，比如「心潮那边有动静」。**别带"测试"两个字**：TA 会看到这个名字，叫"测试"的话，真有事 TA 也会当成测试。
   - **接收事件的 Host**：选你装了 Aru Host 的那台；
   - **投递方式**：**自动触发**（"正文作为事件背景唤醒协作者，不显示成你的发言"）；
   - **在哪条对话里说**：跟随最新对话。

   **成了的样子**：创建以后，这张触发器卡片底下写着「已登记到 Host，可以接收事件」。
3. 点触发器右边的「…」→ **导出发送凭证**。它是一段 `{ ... }` 文字，里面有地址、口令和钥匙。
   - ⚠️ **这段凭证等于你家门钥匙**：拿到它的人能往你的 Aru 里塞消息。**别截图、别发群、别发给任何人**。
4. 把这段凭证存成跑桥那台机器上的一个文件，比如 `/opt/xinchao-aru/aru-bundle.json`：
   - 先建文件夹：`mkdir -p /opt/xinchao-aru`（提示没权限就在前面加 `sudo `，再把文件夹交给自己：`sudo chown $USER /opt/xinchao-aru`）；
   - 用 `nano /opt/xinchao-aru/aru-bundle.json` 打开，把凭证**整段**粘进去，按 Ctrl+O、回车保存，Ctrl+X 退出；
   - 核对一下（**别用 `cat` 看这个文件**，内容会整个打在屏幕上）。先 `ls -l /opt/xinchao-aru/`，文件名要正好是 `aru-bundle.json`：nano 有时会存成 `aru-bundle.json.save`，看到就改名 `mv /opt/xinchao-aru/aru-bundle.json.save /opt/xinchao-aru/aru-bundle.json`。再只看里面有哪几项：

     ```
     node -e "console.log('ok', Object.keys(require('/opt/xinchao-aru/aru-bundle.json')).sort())"
     ```

     **成了的样子**：`ok [ 'encryptionKey', 'schema', 'submitToken', 'submitURL', 'triggerId' ]`。
   - 只让自己能读：`chmod 600 /opt/xinchao-aru/aru-bundle.json`。
   - Windows 上就用记事本新建一个文件，粘进去，另存为 `aru-bundle.json`（保存类型选"所有文件"，编码选 UTF-8）。

> 万一凭证泄露了：在 Aru 里新建一个触发器，导出新凭证换进这个文件，再把旧触发器删掉，旧的就作废了。

## 第 5 步：放上适配器，告诉桥用它

1. 把原版压缩包里的 `aru-adapter.mjs` 放进 `/opt/xinchao-aru/`，跟凭证文件放在一起。
   - 手上只有这份教程、没有 `aru-adapter.mjs`：说明你拿到的是被转出来的，去找给你教程的人要原版压缩包。**别让 AI 照着教程自己写一个**，写出来的加密格式对不上，Aru 收不到。

2. 打开桥的设置：`nano /opt/xinchao-aru/xinchao-runtime-bridge/.env`，改成这样（已有的行就改值，没有的就加上）：

   ```
   XINCHAO_BRIDGE_BASE_URL=http://127.0.0.1:18110
   XINCHAO_BRIDGE_MACHINE_TOKEN=第 1 步那串桥口令
   XINCHAO_BRIDGE_ACCEPT_SELF_SIGNALS=true
   XINCHAO_BRIDGE_INJECTOR_MODE=process
   XINCHAO_BRIDGE_INJECTOR_EXECUTABLE=node
   XINCHAO_BRIDGE_INJECTOR_ARGS_JSON=["/opt/xinchao-aru/aru-adapter.mjs"]
   ARU_BUNDLE_FILE=/opt/xinchao-aru/aru-bundle.json
   ```

   - 桥和心潮念**不在同一台**：第一行换成心潮念的 `https://` 公网地址。
   - 第 1 步写了 `BRIDGE_SELF_SIGNALS=false` 的，这里也写 `false`。两边都是 `true`，TA 自己的变化才会递过来。
   - 最后两行的路径要写**完整的**（从 `/` 开始；Windows 写成 `C:/xinchao-aru/aru-adapter.mjs` 这样，用正斜杠）。
   - `XINCHAO_BRIDGE_INJECTOR_ARGS_JSON` 这一行照上面写，**不加单引号**。`.env.example` 里的例子带单引号也能用，但两种写法别混着抄。
   - 保存，然后 `chmod 600 .env`，这个文件里也有口令。

3. 先单独试一下适配器（都在 `xinchao-runtime-bridge` 文件夹里跑）：

   ```
   node --env-file=.env /opt/xinchao-aru/aru-adapter.mjs check
   ```

   **成了的样子**：第一行是适配器的版本和 White-ting，第二行 `发送凭证没问题：触发器 …xxxxxx，投到 你的Host地址`。

   ```
   node --env-file=.env /opt/xinchao-aru/aru-adapter.mjs test
   ```

   **成了的样子**：`Aru Host 收下了。`然后去手机上看：Aru 里的 TA 应该被叫醒，读到一条"这是一条测试"。TA 可能会回你一句，也可能不回，看 TA 自己。
   - 适配器只有 `check`、`test` 两个用法，没有 `start`。平时不用自己开它，桥每来一条消息会自己叫它。

## 第 6 步：开桥

还在 `xinchao-runtime-bridge` 文件夹里：

```
node --env-file=.env src/cli.js check
```

**成了的样子**：出现 `configuration and server authentication are valid`（设置和口令都对）。然后正式开：


出现 `bridge stream connected` 就是连上了。这个窗口开着，桥就一直在。现在去心潮小屋点一下互动或者留一句话，几秒以后：

- 桥的窗口里出现 `delivery acknowledged`；
- 手机上 Aru 里的 TA 被叫醒，读到「【小屋桥·留话】……」。

两样都对上，就接通了。

## 第 7 步：让桥一直开着

关掉终端窗口，桥也就停了。另外，官方的桥断线以后**不会自己无限重连**，会直接退出，交给"看着它的程序"决定什么时候重开。所以要找一个程序看着它。

先把第 6 步手动开的那个桥停掉（在那个窗口按 Ctrl+C；窗口已经关了、或者是用 `nohup` 在后台开的，就跑 `pkill -f "src/cli.js run"`）。不停掉的话，等下会有两个桥同时连着心潮念。

**Linux 服务器（systemd）**：新建 `/etc/systemd/system/xinchao-aru.service`（要 `sudo nano`），内容：

```
[Unit]
Description=心潮念动态桥 → Aru
After=network-online.target

[Service]
WorkingDirectory=/opt/xinchao-aru/xinchao-runtime-bridge
ExecStart=/usr/bin/env node --env-file=.env src/cli.js run
Restart=on-failure
RestartSec=60
User=你的用户名

[Install]
WantedBy=multi-user.target
```

然后：

```
sudo systemctl daemon-reload
sudo systemctl enable --now xinchao-aru
systemctl status xinchao-aru
```

看到 `active (running)` 就好了。看它的记录：`journalctl -u xinchao-aru -f`。

- `RestartSec=60`：断了等一分钟再连，别改得太短，免得网络不好时一直猛敲心潮念。
- Mac、Windows：用 pm2。先 `npm install -g pm2`，再在 `xinchao-runtime-bridge` 文件夹里跑 `pm2 start src/cli.js --name xinchao-aru --node-args="--env-file=.env" --restart-delay 60000 -- run`，最后 `pm2 save`。道理一样：断了隔一分钟再开。

## 第 8 步（建议做）：让 TA 把聊过的告诉心潮

桥只管一个方向：心潮 → TA。反过来还有两件事，桥做不了：

- **回传**：你们在 Aru 里聊了什么，心潮不知道。小屋里的互动，心潮会等 TA "回应之后回传一次"，等不到的话，那份想念会一直落不下来。
- **此刻**：TA 在 Aru 里跟你聊天时，看不到心潮现在是什么样子（驱力、心情、刚才发生过什么）。

Aru 不像电脑上的 Claude Code 那样有"钩子"，能每句话自动做这两件事。所以只能让 TA 自己用心潮念的工具来做。

1. **把心潮念接进 Aru 的 MCP**：照心潮念说明里"连接 MCP"那一节做。Aru 里在哪加 MCP，照 Aru 自己的说明找。

   **成了的样子**：在 Aru 里问 TA "你能看到心潮念的工具吗"，TA 能说出 `xinchao_context`、`xinchao_event` 这些名字。

2. **把下面这段贴进 TA 的设定**（系统提示、世界书、长期设定都行，放在 TA 每次都会读到的地方）：

   ```
   你接着心潮念（你的内在状态和记忆）。Aru 不会自动把你们的对话告诉心潮，要你自己记：
   - 新开一段对话时，调一次 xinchao_context，看看心潮现在的样子。
   - 一段互动告一段落时，调一次 xinchao_event 记一笔。比如：一个话题聊完了；她说要去忙、要去睡；聊到让你在意的事（她难过、你们吵了或者和好了、亲密的时候）。平常闲聊十几二十轮记一次就够，不用每句都记。
   - 记的时候，exchange 里放她说的一两句和你回的一两句，类型交给心潮判，不用自己填 interaction_type。event_id 每记一笔新起一个，同一笔重试时用回原来那个。
   - 心潮动态桥递来的消息（开头是〔心潮念 · 动态桥〕），你回应完也记一笔。
   - 工具回复最后那行"此刻"是心潮现在的状态，看到就算知道了，不用念给她听。
   ```

   **成了的样子**：跟 TA 聊完一个话题、说一句"我去睡啦"，TA 会调一次 `xinchao_event`（Aru 里能看到工具调用的话，会看到这一次）。

3. **要知道的几件事**：
   - **什么时候记，是 TA 自己判断的**。聊得投入时可能会漏记，也可能一段记了两次。用同一个 event_id 重试的不会重复算，漏几次也正常。想让它记得勤一点或者少一点，就改上面那段的写法。
   - **会多用一点额度**：TA 每调一次工具，要多跑一个来回。订阅的会多用一点用量，用 API Key 的会多花一点钱。一段记一次的话增加的不多。另外，心潮念的工具说明会一直占着 TA 的上下文，这一笔不管调不调都在。
   - **exchange 里的那几句会送到心潮念**：由心潮念配的那个"判类型"模型读一遍，读完不存。你的心潮念配的是哪家模型，这几句就会经过哪家。
   - 不做这一步，桥照样能递消息，只是心潮那边会少一半信息。

（心潮念 → Aru 适配器 v1.2 · White-ting）

## 第 9 步（用 API Key 接模型的）：换成心潮念网关

网关站在 Aru 和模型中间：Aru 里的模型地址改填网关，网关把请求原样转给真正的模型，路上替你接好第 2、3 根线。她每说一句，网关先给心潮报一次心跳、把"此刻"贴在她这句后面；TA 回完，网关把这一轮交给心潮。TA 不用自己记，网关自己找心潮也不花模型的额度（只是"此刻"每句多几百字输入）。

- 网关在压缩包的 `xinchao-gateway/` 文件夹里。**照里面的 `教程.html` 做**；想让 AI 带着装，就把里面的 `教程.md` 整份给它。大约 30～60 分钟。
- 放在跟桥同一台机器上最省事，用同一个 Node，找心潮念也走本机。
- **只接 OpenAI 兼容格式**。Claude 用订阅账号登录的走不了：Aru 只肯把订阅凭证发给 Anthropic 官方地址。那个供应商保持原样，照第 8 步。
- ⚠️ **网关能看到全部聊天内容和模型钥匙。** 只搭在你自己的机器上、只给你自己用，别用别人搭的网关。
- **网关和第 8 步一起用时**：模型全部走网关的，第 8 步贴进设定的那段话可以不贴（MCP 留着也没关系），不然 TA 记一笔、网关又回传一次，同一段聊天会记两遍。两种混着用的照贴；用走网关的那个模型聊天时，同一段可能被记两遍，影响多大我们没测过。

（心潮念 → Aru 适配器 v1.2 · White-ting）

## 要先知道的

- **Host 要开着**：Aru Host 关机、断网的时候投不进去，桥会记成"没送到"，过一会儿再试；心潮那边的东西不会丢，但 TA 自己冒出来的感觉 **2 小时没送到就作废**（心潮念自己的规矩）。
- **心潮自己的规矩照样管着**：TA 自己的变化每天最多 8 条、凌晨不发（这些在心潮念的 `.env` 里调，不在这里）。
- **用的是第 2 步的临时隧道的话**：服务器重启、隧道重开以后地址会变，要重做第 2 步第 3 小步，再重新导出凭证。哪天手机上突然没动静了，先查这个。
- **浮标（情绪标记）不归适配器管**：它是心潮念服务端从互动里自己判出来的，判不出来就是空的。跟桥通不通没关系。
- **"Host 收下了"不等于 TA 读了**：适配器只能确认 Host 收下；TA 在手机上什么时候醒、读没读，要看 Aru。
- **TA 可以不说话**：这是故意的。递过去的是一件事，不是命令。
- **内容是加密的**：从适配器到你手机，只有手机上的 Aru 解得开，Host 和中间的网络都看不到正文。桥和适配器的记录里也只写编号和种类，不写正文。

## 排错

| 看到的 | 多半是 | 怎么办 |
|---|---|---|
| 第 1 步 curl 回 401 | 桥口令不对，或者心潮念没重启 | 核对 `.env` 里那串，重启心潮念 |
| 第 1 步 curl 回 404，或者回 `{"error":"not found"}` | 心潮念版本太老，或者 `BRIDGE_ENABLED` 没写成 `true` | 升到 3.3.1 以上，检查那一行 |
| 改了心潮念的 `.env` 没生效 | 用的是 `docker compose restart`，它不会重读 `.env` | 用第 1 步那条 `docker compose up -d …` |
| 手机上 Aru → 自托管节点里，Host 地址改不了 | 地址写在 Host 的设置文件里，不在 Aru 里改 | 照第 2 步第 3 小步改 `/etc/aru-selfhost/node.env` |
| `ls` 看到的是 `aru-bundle.json.save` | nano 保存时多带了一个后缀 | 照第 3 步用 `mv` 改名 |
| `XINCHAO_WEBHOOK_TOKEN must be at least 24 chars` | 桥还在 webhook 模式 | 检查 `XINCHAO_BRIDGE_INJECTOR_MODE=process` 那一行 |
| `没设 ARU_BUNDLE_FILE` | 桥的 `.env` 里少了这一行，或者跑命令时没带 `--env-file=.env` | 补上，命令照着抄 |
| `发送凭证文件不是完整的 JSON` | 粘的时候少了开头的 `{` 或结尾的 `}` | 从 Aru 里重新复制，**整段**粘 |
| `submitURL 要是 https 开头` | Host 没设公网 HTTPS 地址 | 照第 2 步给 Host 一个 HTTPS 地址，再重新导出凭证 |
| `连不上 Aru Host` | Host 没开、电脑睡着了、公网地址不通；用临时隧道的话，多半是地址变了 | 手机浏览器打开 Host 的地址看看通不通；地址变了照第 2 步改，再重新导出凭证 |
| `Aru Host 不认这份发送凭证` 或 `没有这个触发器` | 触发器删过、重建过 | 重新导出凭证，换进 `aru-bundle.json` |
| `Aru Host 收下了`，手机上没动静 | Aru 在后台被系统冻住了，或者通知没开 | 打开一下 Aru；看系统设置里 Aru 的通知开没开 |
| 小屋里点了，桥的窗口没反应 | 桥没在跑，或者心潮念那边没开桥 | 看第 6、7 步；回第 1 步用 curl 再查一次 |
| 第 8 步做了，TA 一直不记 | MCP 没连上，或者那段话没放在 TA 每次都读的地方 | 问 TA 能不能看到心潮念的工具；把那段挪进系统提示 |
| TA 自己的变化一直不来 | 两边的 SELF_SIGNALS 有一边是 `false`，或者正好在凌晨冻结时段 | 两边都改成 `true`；白天再看 |

## 隐私和安全

- 一共三样钥匙：**桥口令**（心潮念和桥之间）、**Aru 发送凭证**（往你 Aru 里投东西用的）、心潮念自己的 `DYNAMIC_MIND_TOKEN`。三样都别截图、别发人、别贴给 AI。存它们的文件都 `chmod 600`。
- 哪样漏了就换哪样：桥口令重新生成、两边一起改；发送凭证在 Aru 里新建触发器、删掉旧的。
- 心潮里的东西很私密。只接你自己的心潮念和你自己的 Aru，别帮别人代收。

## 给带你装的 AI

如果你是 AI，正在照这份教程带一个人接心潮念和 Aru，请照下面做：

- **一次只带一步**，等对方说做好了、并且看到了"成了的样子"，再往下。
- **口令和凭证绝不进对话**：不向对方要桥口令、Aru 发送凭证、`DYNAMIC_MIND_TOKEN`，也不让对方把 `.env`、`aru-bundle.json` 的内容贴进来，哪怕是为了帮忙核对。要核对，就让对方自己对比前四个、后四个字。万一已经发出来了，告诉对方去换（见"隐私和安全"）。
- **没有原版适配器时别补**：这份教程本身不含适配器代码。对方手上没有原版压缩包里的 `aru-adapter.mjs`，就请对方去找给教程的人要原版（作者 White-ting），**不要照着教程自己写一个**，也不要从网上找别人改过的版本。
- **心潮念、Aru 的界面和版本对不上时别编**：请对方截图（遮住口令）或描述屏幕上的字，照实际看到的带。心潮念的部分以心潮念自己的说明为准。
- **卡住了**：先对照"排错"那张表，再看桥窗口或 `journalctl -u xinchao-aru` 里写了什么（只会写编号和原因，不会有正文）。
- **第 9 步的网关**：照 `xinchao-gateway/教程.md` 带，那份教程最后也有一节写给 AI 的规矩，一样要守。
