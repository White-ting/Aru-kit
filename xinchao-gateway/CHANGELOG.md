# 更新说明

## 0.1.12（2026-11-18）

- **此刻里有黑匣子编号也附得上**（使用者反馈）：心潮的「此刻」在「另外：匣子里 N 条（1 条要提醒你：box-…）」那行会写黑匣子条目的编号，格式是 `box-时间-6位随机`（比如 `box-mwjcto3u-khyqtd`）。随机那段常有 6 个连着的小写字母，撞上硬门「6 个以上连续小写字母」那条，整块此刻被挡（`now-attach skip why=gate`）。现在判断前先去掉黑匣子编号；`xinchao_` 开头的工具名（以前只放过 `xinchao_context`，信封里还会写 `xinchao_box read …`）也一起放过。别的英文键名照样挡。
- **挡下时日志说清是哪条、第几行**：`now-attach skip why=gate rule=word line=3`。`rule`：`word`（6 个以上连着的小写字母或下划线）、`decimal`（小数）、`lines`（超过 8 行）、`len`（超过 400 字）、`not-ok`（心潮说这次没有）。只记规则和行号，不记内容。
- 测试 85 项。

## 0.1.11（2026-11-18）

起因：使用者反馈（Aru Host 0.39.1），潮汐浮标的「原话」经常是英文元数据，不是她说的那句。三种 Aru 自己写、用 user 身份发的消息被当成了她的话。role 都是 user，分不出来，只能看字：
- **引用回复**：她引用一句再回复时，Aru 在她的话前面放了四层——`[Replying to quoted text · reference data]`、换行一段 JSON（被引用的那句、编号、role）、再一行短方括号、然后才是她的话。以前整段当她说的，存下来的前 40 字全是方括号和 JSON。现在开头这几层整块去掉：方括号按配对数；JSON 要括号配得上、而且真能解析才去（她自己打的 `{…}` 不会被吃）；短方括号要单独占一行才去。只引用、一个字没说的，不算她在说话（`skip why=annotation`）。照使用者 `DEBUG_SHAPE=2` 抓到的骨架拼了测试样本，骨架五段一字不差。
- **桥叫醒**：`External event data, not an authored user message…` 开头（前面多个 `[` 也认），或者里面写着 `not an authored user message` 的，不算她在说话（`turn ok kind=skip why=external`）。
- **工具取回的图**：Aru 把工具取回的图（比如 `fetchPhotoAttachment`）另起一条 user 消息发，开头 `Images returned by the completed tool call…`。以前当成她说的话（还被判成了「吃醋」）。现在当工具回合，工具走完跟她前面那句配成一轮回传（`turn ok kind=tool after=tool-note`）。新配置 `TOOL_PREFIXES`，默认 `Images returned by|Tool result|Tool output`，用 `|` 分隔。
- 发给模型的那份照旧一个字不动，只是回传和判断时去掉。
- 测试 83 项（`test/v0111.test.mjs`）。

## 0.1.10（2026-11-07）正式版

- **日志分清"跳过"和"出错"**：以前照规矩跳过也写成 `fail`，两位测试者的 AI 都把 `event fail why=throttled` 读成了故障（一号的建议）。现在每行第三个词四种：`ok` 做成了；`skip` 照规矩跳过（`event skip why=throttled`、`now-attach skip why=throttled / gate`、`event skip why=tool-no-pending / tool-expired`）；`wait` 在等工具走完（`event wait why=tool-calls`）；`fail` 只留给真出错（连不上、401、`empty-reply` 这类要动手处理的）。
- 0.1.4 起的多渠道一号测过（启动列渠道、`/<口令>/a/v1` 和 `/b/v1` 分流、日志 `ch=`），0.1.9 的工具回合二号在真 Aru 里测过（工具连调两次后 `event ok`）。随适配器 v1.2 正式发。
- 测试 76 项。

## 0.1.6（2026-11-06）

照二号 b71a 的骨架日志改（`DEBUG_SHAPE=2`）：

- **单个标签也去掉**：Aru 的发送时间是 `<sent_at 2026-11-06 21:46>`，只有开头没有结尾、时间写在标签里，接在她那句后面另起一行。0.1.4 只认成对的，没去掉。
- **一轮里她连着发的几条都算**：带环境时 Aru 拆成两条，先是她的话，再单独一条 `<environment>…</environment>`。0.1.4 只看最后一条，那条去完附注没字了，就按"删光了照原样"把整段环境当成了她的话（二号看到的 `clean=2616 raw=2616`）。现在取最后一条 TA 的回复之后她发的所有条，每条去掉附注再拼起来。
- **只有附注、没有她的话的一轮**不算她在说话：`turn ok kind=skip why=annotation`，不报心跳、不回传。
- **骨架遮干净**：标签里只留标签名，写在标签里的时间、属性也换成字数（0.1.5 会把 `<sent_at 2026-11-06 21:46>` 里的时间照写出来）。
- `shape ok clean= raw= n=`：`raw` 改成这一轮那几条一共几个字，`n` 是去掉附注后还有字的条数。
- 测试 72 项（新加 `test/v016.test.mjs` 4 项，按二号日志里的真实写法造的）。

## 0.1.4（2026-11-06）

- **去掉 App 塞进她那句的附注**（测试反馈 ca3e）：Aru 带附注时会把 `<sent_at>…</sent_at>`、`<environment>…</environment>`（两千多字）并进她的话里。回传给心潮、判断桥消息、判断后台杂活之前先整块去掉，只留她自己打的字；发给模型的那份不动。`STRIP_TAGS`：`*`（默认，所有成对英文标签）/ 名单 / 空（不去）；去完没字了就照原样。`turn … chars=` 现在是去掉附注后的字数；`DEBUG_SHAPE=1` 多一行 `shape ok clean= raw=`。
- **多渠道**（测试反馈 3bcb）：`.env` 里 `UPSTREAM_<名字>_URL` / `UPSTREAM_<名字>_KEY` 成对写，App 地址写 `/<名字小写>/v1` 就走那一家，不写名字走 `UPSTREAM_URL`。在几家中转站之间换着用时，只在 App 里改地址，网关不用改。名字不分大小写；能跟地址口令叠着写 `/<口令>/<名字>/v1`；某一家写 `passthrough` 就用 App 自己的钥匙（只认地址口令）。启动时列出渠道，日志 `request … ch=名字`，401 的日志里渠道名照写、口令遮住。启动检查：两行要一起写、不能叫 v1/healthz、不能跟 `GATEWAY_KEY` 撞。

- **调试开关 `DEBUG_SHAPE=1`**：日志多记她那句话的结构（几块、每段几个字、前几条几个字、`<标签>` 名字），不记正文。用来看 App 往她那句里塞了什么。

## 0.1.2（2026-11-04）

- **透传模式**（给 Aru 里用「订阅账号」登录 Claude 的人）：`.env` 写 `UPSTREAM_KEY=passthrough`。
  - App 带来的 `authorization`、`x-api-key`、所有 `anthropic-*` 请求头，和地址后面的查询参数，原样转给上游；
  - 两根线、流式、后台杂活判断、节流不变。
- **地址口令**：Base URL 写成 `https://你的地址/<GATEWAY_KEY>/v1`。
  - 网关用常数时间比较核对口令，对了去掉这一段再处理，对不上或者没带回 401，不碰上游。
  - 透传模式只认地址口令；普通模式下地址口令和请求头口令二选一。
- **日志**：`path=` 里的口令那一段换成 `***`，401 的日志也一样。
- **`/healthz`**：照旧不要口令；`/<口令>/healthz` 也回同样内容，口令错了回 401。
- **小变化**：除了 `/healthz`、`/v1/...` 以外的地址，第一段都当成地址口令核对，对不上回 401（以前是 404）。
- **启动检查**：透传模式下 `GATEWAY_KEY` 只能用字母、数字和 `. _ ~ -`。
- **按格式分上游**（两种混着用的，比如 DeepSeek + Claude 订阅）：
  - 新增 `ANTHROPIC_UPSTREAM_URL`、`ANTHROPIC_UPSTREAM_KEY`，可以不填。
  - 填了，`/v1/messages`（和 `/v1/messages/...`）走这一组，别的路径还走 `UPSTREAM_*`。
  - 每组的 KEY 都能单独写 `passthrough`。哪组是透传，去那组的请求就只认地址口令。
  - 此刻、回传、节流共用一份。两项要一起填，少一项启动时报错。
- **测试** 56 项（新加 14 项：`test/passthrough.test.mjs` 8 项、`test/split.test.mjs` 6 项）。
